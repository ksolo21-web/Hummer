# Phase3C dependency sequence and first transaction gate

Original Phase3C scope is preserved: validated preparation plus controlled geometry/assignment/inventory editing. This first bounded dependency (3C-A) supplies the conditional preparation transaction. Full3C is NOT complete when3C-A passes.

Remaining3C-B: extended typed durable proposals for geometry, assignment and address/telephone inventory; known IDs/before-values; per-category authority; integrated adaptive editors and change review; independent revalidation of all changed dependencies. Remaining3C-C: connect these and label drafts to the validated-preparation UI with actual phone/wide Light/Dark evidence and no-authority blocked paths.3D remains aggregate editing integration audit. Reserved six remainPhase7.

3C-A mandatory acceptance:
1. Require current saved nonempty road-label draft, exact optimistic token, known territory/mode, current source/base and independently verified prepared baseline. Draft strings alone cannot manufacture input, assignment authority or provider results.
2. Consume independently reconciled full input. Exact saved proposals must match labels; reject undeclared geometry/role/item changes, normalized-name drift, metadata/source-truth drift and changed jurisdiction. Rebuild exact provider request from edited targets and trusted baseline jurisdiction.
3. Deep-detach every input/inventory/provider data record including nested collections and fields outside canonical hashes. Bound graph depth/size; unsupported records fail closed. External mutation cannot alter validation/prepared state.
4. Execute production live verification with cache BYPASS; ignore submitted decisions/results, reconcile returned provider evidence using existing policy, and run frozen production adapter and inventory validators. No copied success booleans or missing provider quorum fallback.
5. Issue opaque bounded session ticket binding exact draft identity/token/base, source import identity, input/inventory hashes, expected prior candidate version and five-minute commit lifetime. Explicit prepare consumes once; forged, cancelled, expired or stale tickets reject.
6. Conditional coordinator installation preserves old valid preparation on failure. New preparation replaces candidate version and clears old front/packet. Later draft/source/input changes make the guarded preparation, preview and review unavailable. Existing approved export stays separate.
7. Exercise Letter/Telephone positive synthetic build/packet paths and unavailable-number preservation; meaningful negative source/draft/target/authority/geometry/inventory/mutation/concurrency cases. No real commissioning or approval inferred.
8. Preserve87 accepted identities; run only new/affected tests. UI/core/3A draft store/assets frozen. Package/source integrity, independent score >9 target10, durable checkpoint and readback.

No new UI acceptance is claimed in3C-A. Existing label editor does not expose preparation until3C-C; services are registered internally for the dependent workflow.

Building-label preparation remains explicitly blocked until3C-B: changing an actual rendered single-building label also changes its verified member inventory. The frozen adapter requires these to agree.3C-A must reject building proposals before provider execution or candidate replacement; no display-only fixture may be used to claim this capability.3C-B retains authority-aware building reconciliation as mandatory scope.

Inventory is snapshotted atomically with the independently prepared baseline and must remain structurally identical for this road-label transaction. Null inventory is an explicit front-only reduction; it blocks Page2. Changed address/telephone records require3C-B authority-aware reconciliation even when structurally valid.

All detail/layout fields and building validation must equal the detached prepared baseline. Labels may change only the saved road text and corresponding navigation-lock street text; placement and unrelated labels stay exact. Wider layout/placement editing remains3C-B.
